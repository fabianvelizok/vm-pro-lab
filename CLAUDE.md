# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
npm install

# Development: serve locally (no build step needed)
python3 -m http.server 8000
# or
npx serve .

# Production build (clean + sync critical CSS + minify CSS/JS/HTML + copy assets + extras)
npm run build

# Preview production build locally (requires Wrangler)
npx wrangler pages dev dist/

# Individual build steps
npm run clean          # Remove dist/
npm run sync:critical  # Re-generate inline critical CSS in index.html from css/styles.css
npm run minify:css     # CSS → dist/css/styles.min.css
npm run minify:js      # JS  → dist/js/main.min.js
npm run minify:html    # HTML → dist/index.html (updates asset references)
npm run copy:assets    # Copy fonts, images, and icons to dist/
npm run copy:extras    # Copy robots.txt, favicon.ico, and _headers to dist/
```

Node.js ≥ 22 required (see `.nvmrc`). No test suite.

## Architecture

Single-page marketing site. Zero runtime dependencies — pure HTML5, CSS, and vanilla JS.

**Source files (edit these):**
- `index.html` — The entire page. Loads `css/styles.css` via a `preload`+`onload` async trick with a `<noscript>` fallback.
- `css/styles.css` — Full stylesheet with CSS custom properties. Dark mode via both `prefers-color-scheme` (initial) and a `[data-theme="dark" | "light"]` override set by the JS theme toggle.
- `js/main.js` — IIFE-wrapped, initializes on `DOMContentLoaded`: theme toggle (with `localStorage` under `vm-theme`), sticky header, mobile menu with focus trap, active nav via `IntersectionObserver`, contact form (self-hosted Cloudflare Worker + Resend, with honeypot + toast notifications), lazy-load Devicon CSS.

**Build output (do not edit):**
- `dist/` — Generated by `npm run build`. Minified assets with updated references.

### Production Deployment

Deployed on **Cloudflare Pages**. Caching headers are defined in the `_headers` file (copied to `dist/` during build). No server runtime needed.

### Key Patterns

**Performance:** Devicon is lazy-loaded via `IntersectionObserver` only when the `#technologies` section nears the viewport.

**Critical inline CSS:** Above-the-fold styles are inlined in `index.html` between `<!-- CRITICAL-CSS-START -->` and `<!-- CRITICAL-CSS-END -->` markers. **Never edit this block by hand** — it is auto-generated by `scripts/sync-critical-css.js` (`npm run sync:critical`), which extracts and minifies the relevant rules from `css/styles.css`. Run it after any stylesheet change that affects above-the-fold elements, or it runs automatically as the first step of `npm run build`.

**CSS naming:** No BEM. Use simple descriptive class names (`.nav-link`, `.btn-primary`). Always extend from base classes — all buttons inherit from `.btn`.

**CSS custom properties** are the design system. All colors, spacing, typography, and layout values are defined in `:root` in `css/styles.css`. Use them; don't hardcode values.

**Accessibility:** WCAG 2.1 AA target. Every interactive element needs keyboard support, ARIA labels, and sufficient color contrast. The mobile menu implements a full focus trap. Skip link is present.

**Images:** WebP with JPG fallback using `<picture>` elements. Lazy-load non-critical images.

**Contact form:** JS-only submission — no `action`/`method` on the `<form>` element. `initContactForm()` in `js/main.js` POSTs JSON to a hard-coded `WORKER_URL` constant that points at the self-hosted Cloudflare Worker (`vmprolab-contact-worker.js`, kept **outside** this repo). The worker validates, rate-limits via KV (3/hour/IP), and delivers branded email via Resend. Frontend success/error feedback is shown via the success-toast / error-toast elements in `index.html` — do not add inline status text back; the toasts are the only user-facing feedback. A hidden honeypot field (`#hp-website`) silently aborts bot submissions.

## Design Tokens

| Token | Light value | Dark value | Notes |
|---|---|---|---|
| `--color-text` | `#0F172A` | `#E4E8F7` | Main text / brand |
| `--color-text-light` | `#44556A` | `#A8B2E0` | Secondary text |
| `--color-accent-hover` | `#1D4ED8` | `#4285F4` | Eyebrow, interactive accent (6.41:1 on light bg) |
| `--color-accent-blue-light` | `#8AB4F8` | `#8AB4F8` | Dark-mode eyebrow, decorative accents |
| `--color-accent-cyan` | `#00D4FF` | `#00D4FF` | CTAs, focus rings, gradient start |
| `--color-accent-cyan-text` | `#0E7490` | `#00D4FF` | Accessible cyan for text (AA compliant) |
| `--color-accent-blue` | `#4285F4` | `#4285F4` | Gradient end |
| `--color-success` | `#047857` | `#34D399` | Success states (4.52:1 light / 7.5:1 dark) |
| Font | Inter (self-hosted WOFF2) | — | Weights: 400, 600, 700 |

> Avoid `opacity` hacks for color; use the token directly to preserve contrast ratios.

## Agents

Specialized Claude Code agents are configured in `.claude/agents/`:

- **`vanilla-frontend-engineer`** — Implements features in pure HTML/CSS/JS. Invoke for any UI work.
- **`accessibility-auditor`** — Audits WCAG compliance, ARIA, contrast, keyboard nav. Runs automatically on UI changes.
- **`web-performance-auditor`** — Runs Lighthouse, checks Core Web Vitals. Invoke after builds.
- **`design-system-auditor`** — Validates CSS token usage, naming consistency, pattern adherence.
- **`frontend-designer`** — Creates distinctive, production-grade frontend interfaces. Use when building new components, pages, or sections.
- **`task-architect`** — Transforms informal requirements and meeting notes into structured, actionable technical tasks under `.claude/todos/`.

Audit reports are saved to `docs/`.
